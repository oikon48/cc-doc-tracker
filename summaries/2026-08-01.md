**URL:** https://code.claude.com/docs/en/agent-sdk/agent-loop.md

**変更の概要:** パーミッションモードの一覧表に **「Use case（推奨ユースケース）」列が追加** され、各モードをいつ使うべきかが明示されるようになりました。あわせて `"default"` モードの説明が `canUseTool` コールバックへの言及を明示する形に更新され、`"bypassPermissions"` モードに TypeScript SDK 固有の注意事項（`allowDangerouslySkipPermissions: true` が必要）が追記されました。

**変更前後の対比:**

| モード | 変更前の説明 | 追加された Use case |
|---|---|---|
| `"default"` | Tools not covered by allow rules trigger your approval callback | Interactive applications with a custom approval callback |
| `"acceptEdits"` | Auto-approves file edits and common filesystem commands | You trust Claude's edits and want faster iteration, such as during prototyping or when working in an isolated directory |
| `"plan"` | Claude explores and plans without editing your source files | You want Claude to propose changes without executing them, such as during code review or when you need to approve changes before they're made |
| `"dontAsk"` | Never prompts. Tools pre-approved by permission rules run | You want a fixed, explicit tool surface for a headless agent and prefer a hard deny over silent reliance on `canUseTool` being absent |
| `"auto"` | Uses a model classifier to approve or deny permission prompts | Autonomous agents that still want safety guardrails on tool use |
| `"bypassPermissions"` | Runs all allowed tools without asking（+ TypeScript SDKは `allowDangerouslySkipPermissions: true` が必要と追記） | CI, containers, or other isolated environments |

**ポイント:** ドキュメントを読むだけでどのモードを選べばよいか即座に判断できるようになりました。
